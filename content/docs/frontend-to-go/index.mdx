## 一套餐厅故事贯穿 Runtime

为了避免从一个技术术语直接跳到另一个术语，10 篇已验证专题增加了统一的餐厅故事层：

| 餐厅角色 | Go 概念 | 先记住什么 |
| --- | --- | --- |
| 订单、厨师、工位 | G、M、P | 订单很多，真正执行的人和工位有限 |
| 传菜口与托盘位 | Channel 与 Buffer | 能暂存不等于不会堵 |
| 多个取餐铃 | select | 一次选一个，其他任务不会自动取消 |
| 仓库钥匙与计数器 | Mutex 与 Atomic | 多步不变量和单点更新不是一回事 |
| 取餐震动器 | Netpoll | 等待网络时不必占住系统线程 |
| 工作台与总仓库 | Stack 与 Heap | 生命周期决定东西放在哪里 |
| 清洁员与餐具 | GC | 仍有人使用的对象不能回收 |
| 八格订单抽屉 | Swiss Table Group | 先批量筛选候选，再核对真实 Key |
| 岗位能力要求 | Interface 与 Method Set | 会规定动作就能满足契约 |
| 下班清单与火警 | defer、panic、recover | 清理、异常和隔离是三件事 |

每个故事都会紧跟“换回技术语言”和“类比到这里为止”。比喻负责建立直觉，规范、固定版本源码和实验仍然负责证明结论。

## 类比关系怎么读

| 关系 | 含义 |
| --- | --- |
| 同一抽象 | 解决的问题基本一致，可以迁移已有认知 |
| 部分类比 | 适合建立入口，但实现和约束不同 |
| 危险类比 | 表面相似，直接照搬会产生错误设计 |
