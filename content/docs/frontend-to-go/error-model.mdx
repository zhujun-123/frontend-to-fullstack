## JavaScript 的常见写法

```ts
try {
  const user = await getUser(id);
  return user;
} catch (error) {
  logger.error(error);
  throw error;
}
```

## Go 的常见写法

```go
user, err := getUser(ctx, id)
if err != nil {
    return User{}, fmt.Errorf("get user %s: %w", id, err)
}

return user, nil
```

## 服务端真正需要解决的不是“捕获”

错误在不同层有不同职责：

- Repository：保留数据库或者外部依赖的错误原因。
- Service：增加业务上下文，识别可重试和不可重试错误。
- Handler：转换成稳定的状态码和响应体。
- Middleware：统一记录请求 ID、耗时和未处理错误。

## `panic/recover` 不等于 `throw/catch`

参数错误、记录不存在、依赖超时等都是业务运行中可预期的情况，应当返回 `error`。`panic` 更适合表示程序进入了无法继续保证正确性的状态，或者在进程边界防止单次请求让整个服务崩溃。
