## 不从“学完一门语言”开始

前端开发者已经具备需求理解、接口联调、状态管理、错误处理和工程化经验。真正需要补齐的，是浏览器之外的软件生命周期。

## 第一阶段：能够修改接口

- 使用 Go 启动一个 HTTP 服务。
- 看懂 Route、Handler、Service、Repository 的职责。
- 接收参数、校验数据、返回 JSON。
- 学会阅读日志和定位错误堆栈。

完成标准不是“记住语法”，而是能在现有项目里安全地增加或修改一个简单接口。

## 第二阶段：理解数据

- 表、字段、主键、外键和唯一约束。
- SQL 查询、分页、索引和执行计划。
- 事务边界以及接口重试带来的重复写入。
- 数据库迁移和上线兼容性。

## 第三阶段：建立服务端思维

- 服务端校验不能依赖前端校验。
- 错误需要分类、记录并转换成稳定的接口响应。
- 共享状态必须考虑并发安全。
- 超时、取消、重试和幂等需要一起设计。
- 服务重启后，关键状态不能只保存在进程内存里。

## 第四阶段：完成一次上线

- 编写单元测试和接口测试。
- 使用 Docker 构建运行环境。
- 理解环境变量、密钥和配置差异。
- 设置健康检查、日志、指标与告警。
- 准备发布、回滚和生产排查方案。

## 第五阶段：逐步进入系统设计

当单个服务已经能够稳定交付，再学习缓存、消息队列、限流、熔断、多服务调用和分布式一致性。不要为了“架构高级”提前引入复杂度。
